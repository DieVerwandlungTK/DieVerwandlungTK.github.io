# Research Homepage Implementation Plan

**Goal:** Build a static research homepage with vgpu playback of reproducible water data.

**Architecture:** Separate offline simulation, validated trajectory loading and
sampling, GPU presentation, and semantic HTML content. Ship generated data so Python
is not needed to build or visit the site.

**Tech Stack:** TypeScript, Vite, vgpu 0.4.0, Python/NumPy/Numba, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-07-homepage-design.md`

## Constraints
- Placeholder personal content; no fabricated publications.
- mW single-site water, actual forward trajectory, model attribution.
- Reduced motion and static fallback; responsive layout and relative asset paths.

## Tasks
- [x] Simulation: `scripts/generate_trajectory.py`, `scripts/test_simulation.py`,
  `public/data/water.json`. First test analytical forces against independent finite
  differences of potential energy and zero net force; then implement two- and
  three-body mW forces, periodic boundaries and Langevin BAOAB integration. Generate
  216-particle heating trajectory with seed 22039. Record energy, temperature, MSD
  and tetrahedral order for reproducibility. Run Python unittest before generation.
- [x] Playback: `src/trajectory.ts`, `tests/trajectory.test.ts`. Test boundary
  interpolation (9.8 to 0.2 in box 10 goes through boundary), clamped endpoints,
  malformed/nonfinite data rejection; implement `validateTrajectory(value)` and
  `sampleFrame(data, progress, output)` returning interpolated positions.
- [x] Presentation: `index.html`, `src/main.ts`, `src/background.ts`,
  `src/style.css`, `src/particles.wgsl`. Implement instanced sphere impostors using
  vgpu and a static molecular SVG fallback. Expose scrubber, pause and replay;
  never advance while hidden or reduced motion is active. Keep text readable and
  all controls accessible by keyboard. Add source links in an expandable caption.
- [x] Delivery: `.github/workflows/pages.yml`, `README.md`, Vite/TypeScript config.
  Run unit tests and production build. Use Playwright for desktop/mobile layouts,
  controls, reduced motion, fallback, asset load failures, project-subpath loading,
  and GPU shader errors. Review diff and record observed validation results.
